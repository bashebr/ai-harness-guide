AI Engineering Architectural Guide

Understanding the architecture behind foundational models and the software frameworks that wrap them.

Bare Model vs. The Harness

In AI engineering, the bare model is the raw, frozen neural network that predicts the next token, whereas the harness is the surrounding software infrastructure that turns those raw predictions into a usable, safe application.

Think of the bare model as a high-performance engine, and the harness as the entire car (dashboard, fuel lines, steering wheel, and safety brakes) that allows a driver to actually steer it.

Feature The Bare Model (The Engine) The Harness / Framework (The Car)
What it is A giant file of mathematical weights (e.g., .safetensors or .bin). The surrounding Python, TypeScript, or Go code and infrastructure.
Primary Job Receives a sequence of tokens and predicts the next mathematical token. Handles user inputs, formats prompts, manages memory, and executes code.
State Stateless. It does not remember past messages natively. Stateful. It stores conversation history in a database or local cache.
Capabilities Strictly limited to token generation. Cannot access the web or run code. Can orchestrate tools, search the web, read files, and run code sandboxes.
Example gpt-4o, llama-3-70b raw weight checkpoints. LangChain, LlamaIndex, OpenAI Assistants API, or a custom wrapper.

Deep Dive: Core Responsibilities of a Harness

1. Prompt Templating

The bare model has no native concept of a "chat interface," "user," or "assistant." The harness wraps user inputs into system instruction envelopes (e.g., <|im_start|>system...) to direct the model's behavior safely.

2. Context Window Management

When conversations exceed token limits, the harness dynamically truncates, summarizes, or prunes history so the bare model never overflows its fixed maximum token threshold.

3. Tool Calling (Function Calling) Loop

When a model decides it needs real-time information, it emits a specific data token. The harness catches this request, pauses generation, runs the actual native API tool (e.g., a SQL query or web search), appends the result to the history, and re-invokes the model.

Building Your Own Harness: Starter Architecture

To build a custom harness in Python, your application loop should look similar to this architecture:

import openai

class CustomHarness:
    def __init__(self, system_prompt):
        self.client = openai.OpenAI()
        self.memory = [{"role": "system", "content": system_prompt}]

    def chat(self, user_input):
        # 1. State management (Save history)
        self.memory.append({"role": "user", "content": user_input})
        
        # 2. Invoke the bare model via API
        response = self.client.chat.completions.create(
            model="gpt-4o",
            messages=self.memory
        )
        
        reply = response.choices[0].message.content
        
        # 3. Save assistant response to state
        self.memory.append({"role": "assistant", "content": reply})
        return reply
